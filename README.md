<h1 align="center">Music Scan Integrity</h1>

<p align="center">
  Проверка музыкальной коллекции на повреждённые файлы. Windows 10/11, офлайн.

Программа находит файлы, которые физически повреждены и не проигрываются, отличая их
от файлов, которые просто без тегов или выглядят необычно, но на самом деле в порядке.

Работает офлайн, только читает файлы — ничего не удаляет, не переименовывает и никуда
не отправляет. Ставится установщиком или распаковывается из архива — переносимую папку
можно просто скопировать куда угодно.

Файл проверяется дважды: декодером — что из него читается звук, и разбором самого
формата — сходятся ли контрольные суммы, записанные внутри файла. Второе даёт точный
ответ там, где первое отвечает лишь «открылось»: обрезанный FLAC декодер прочитает,
а сверка сумм и заявленной длины покажет, что файла не хватает.

Глубина чтения выбирается в настройках: быстрая читает только начало, выборочная
(по умолчанию) — начало, конец и три места в середине, полная — файл целиком.

Отдельной настройкой включается слежение за порчей: программа запоминает отпечаток
каждого файла и на следующей проверке замечает подмену содержимого при неизменных
размере и дате — так выглядит сбойный диск.

> **[docs/INTERNALS.md](docs/INTERNALS.md)** — как всё устроено внутри: методы
> проверки, работа с BASS, движок, отчёты.

## Сборка и запуск

### Что нужно

| Требование | Версия |
|---|---|
| Windows | 10 или 11, 64-бит |
| .NET SDK | 10.0 или новее |
| PowerShell | 7+ (для скриптов из `tools/`) |
| Inno Setup | 6+ — только если собираете установщик |

### Шаг 1. Скачать библиотеки BASS

Декодирование аудио выполняет библиотека BASS (зафиксировано в спецификации).
Её бинарники распространяются un4seen developments по собственной лицензии и в
репозиторий не входят — их нужно скачать один раз перед первой сборкой:

```bash
pwsh tools/fetch-bass.ps1
```

Скрипт положит 64-битные DLL в `native/bass/x64/`, откуда сборка скопирует их
в подпапку `bass\` рядом с исполняемым файлом. Всего двенадцать файлов: `bass.dll`
(ядро — WAV, AIFF, MP3, OGG) и плагины `bassflac`, `bassalac`, `bassape`, `basswv`,
`bassopus`, `basswma`, `bassdsd`, `bassmidi`, `bass_aac`, `bass_mpc`, `bass_tta`.

Если какая-то библиотека не скачалась, программа всё равно запустится — просто файлы
соответствующего формата проверить не получится, и она честно об этом скажет.
Библиотеки можно положить в `native/bass/x64/` и вручную, взяв их с
[www.un4seen.com](https://www.un4seen.com/).

> **Лицензия BASS.** Бесплатна для некоммерческого использования. Для коммерческого
> нужна лицензия un4seen developments — см. условия на их сайте.

### Шаг 2. Собрать

```bash
dotnet build MusicScanIntegrity.sln -c Release
```

### Шаг 3. Запустить

```bash
dotnet run --project src/MusicScanIntegrity.App -c Release
```

### Переносимая сборка для передачи другим

```bash
pwsh tools/publish.ps1
```

Готовая программа окажется в `artifacts/publish/`. Папку можно скопировать на флешку
или отдать другому человеку — .NET на его компьютере не нужен, всё лежит внутри.

### Установщик

```bash
pwsh tools/make-setup.ps1
```

Скрипт сам находит Inno Setup, собирает переносимую версию и заворачивает её
в `artifacts/Music_Scan_Integrity-<версия>-setup.exe`. Сценарий установщика —
[`installer/MusicScanIntegrity.iss`](installer/MusicScanIntegrity.iss): выбор языка,
лицензионное соглашение, папка (по умолчанию «Program Files»), значки на рабочем
столе и в меню Пуск.

> **Предупреждение Windows при первом запуске.** Сборка не подписана цифровым
> сертификатом, поэтому SmartScreen может показать «Windows защитила ваш компьютер»
> и «Неизвестный издатель». Это ожидаемо для программы без подписи: нужно нажать
> «Подробнее» → «Выполнить в любом случае». Предупредите об этом тех, кому передаёте
> программу.

### Готовые сборки

Собирать самому не обязательно: в [разделе Releases](../../releases) лежат установщик
`…-setup.exe` и переносимый архив `…-win-x64.zip`. Внутри одно и то же — установщик
заворачивает ту же самую сборку.

## Сборка в CI и выпуск релизов

Настроены два процесса GitHub Actions.

| Файл | Когда запускается | Что делает |
|---|---|---|
| [`.github/workflows/ci.yml`](.github/workflows/ci.yml) | коммит в `main`, pull request, вручную | Собирает и прогоняет все тесты. Переносимую версию прикладывает только при ручном запуске и хранит сутки: бесплатного хранилища Actions — 0,5 ГБ на аккаунт, а сборка весит 65 МБ |
| [`.github/workflows/release.yml`](.github/workflows/release.yml) | тег вида `v1.2.3` или запуск вручную | Прогоняет тесты, собирает переносимую версию и установщик Inno Setup, считает контрольные суммы и публикует выпуск |

Выпустить релиз:

```bash
git tag v1.3.0
git push origin v1.3.0
```

Либо вручную — вкладка **Actions → Релиз → Run workflow**, указав версию;
тег будет создан автоматически.

Версия из тега подставляется в сборку (`-p:Version=`), поэтому номер в свойствах
исполняемого файла и в окне «О программе» совпадает с номером выпуска.

Релизная сборка не выпускается без библиотек BASS: отдельный шаг проверяет, что они
скачались и попали в архив, — программа без декодера бесполезна.

## Как пользоваться

1. Указать папку с музыкой — кнопкой «Выбрать папку» или перетащив папку прямо в окно.
2. Программа сама быстро посчитает подходящие файлы и предложит начать: искать кнопку
   «Старт» не нужно.
3. Идёт проверка — видно прогресс, счётчики и текущий файл. Паузу и остановку можно
   нажать в любой момент, окно остаётся отзывчивым.
4. По завершении — таблица со статусом каждого файла, отчёт и экспорт.

### Что означают статусы

| Статус | Что это значит |
|---|---|
| ✓ **В порядке** | Файл прочитан и декодирован без ошибок |
| ✕ **Повреждён** | Декодер прервался, поток битый, файл пустой или до него не удалось добраться |
| ! **Предупреждение** | Файл читается, но что-то странно: нет тегов, расширение не совпадает с содержимым, проверка затянулась |
| – **Пропущен** | Файл был занят другой программой и пропущен по решению пользователя |

Статус никогда не передаётся одним лишь цветом: рядом всегда значок и слово.

### Горячие клавиши

| Действие | Клавиши |
|---|---|
| Выбрать папку | `Ctrl` + `O` |
| Начать проверку | `F5` |
| Экспорт отчёта | `Ctrl` + `S` |
| Настройки | `Ctrl` + `,` |

### Поддерживаемые форматы

**Аудио:** WAV, AIFF, FLAC, ALAC, M4A, APE, WV, MP3, AAC, OGG, Opus, WMA
**Трекерные и MIDI:** MIDI, MOD, XM, IT, S3M
**DSD:** DSF, DFF
**Плейлисты:** M3U, M3U8, PLS, CUE

Образы дисков ISO (SACD) — отдельная экспериментальная настройка, по умолчанию
выключенная: обычный `.iso` — это образ диска, а не музыка.

### Где лежат настройки

Рядом с программой, в подпапке `config\settings.json` — программа ничего не пишет
в реестр. Если папка программы недоступна на запись (а после установки в «Program
Files» это именно так), настройки уходят в `%APPDATA%\MusicScanIntegrity\`, а база
отпечатков для слежения за порчей — в `%LOCALAPPDATA%\MusicScanIntegrity\`. База
лежит отдельно намеренно: настройки небольшие и их разумно переносить между
компьютерами, а отпечатки коллекции привязаны к конкретной машине. Точный путь
показан внизу экрана «Настройки».

### Тесты

```bash
dotnet test
```

432 теста в двух проектах. Ядро проверяется целиком, интерфейс — в тех местах,
где ошибку не видно глазами: ход переключателей при смене настройки анимаций,
работа с замороженными преобразованиями WPF, сглаживание кромок в обеих темах.

Тестами покрыто ядро: разбор плейлистов всех форматов и разворачивание относительных
путей, хранение настроек и восстановление после повреждённого файла, реестр форматов,
обход папок, весь конвейер проверки файла (не найден, пустой, битый, защищённый,
таймаут, несовпадение расширения, отсутствие тегов, занятость), движок проверки
(параллельность, пауза, остановка, порционная отдача результатов, критический сбой),
очередь вопросов о занятых файлах, удаление временных копий и экранирование
спецсимволов во всех трёх форматах отчёта.

## Принятые решения по неоднозначным местам

Спецификация оставляла часть решений на усмотрение разработчика. Что было решено и почему:

| Место | Решение |
|---|---|
| Отдельного статуса «ошибка» нет | Спецификация вводит ровно четыре статуса. «Файл не найден», «нет доступа» и «ошибка декодирования» ложатся в **Повреждён** (красная категория), но конкретная причина всегда показана текстом — «файл не найден» не выглядит как «битое аудио» |
| «Эксклюзивный доступ на чтение» | Файл считается занятым, только если его не удаётся открыть на чтение с разделением `ReadWrite`. Открытие с `FileShare.None` объявляло бы занятым любой файл, открытый проигрывателем, — при том что декодировать такой файл прекрасно можно |
| Временная копия занятого файла | Если владелец держит файл вообще без разделения доступа, скопировать его тоже нельзя. Программа честно сообщает «сделать временную копию не удалось», а не делает вид, что проверила файл |
| «Закрыть программу-владельца» | Программа сама чужие процессы не закрывает: это опасно. Вариант показывается в вопросе, только если владелец достоверно определён и включена соответствующая настройка |
| Вопрос о занятом файле | Показывается карточкой на вкладке «Проверка», а не отдельным окном: не перекрывает ход проверки и не блокирует очередь. Если пользователь смотрит другую вкладку, программа переключает его на «Проверку» |
| Где хранить настройки | Сначала пробуем папку программы (переносимость), при недоступности — `%APPDATA%` |
| Разделитель CSV | Точка с запятой и UTF-8 с BOM: русский Excel по умолчанию ждёт именно их. Первой строкой идёт директива `sep=;` |
| Межбуквенный интервал | В WPF нет свойства letter-spacing. Прописные микрозаголовки получают трекинг через типографскую функцию OpenType `CapitalSpacing`; отрицательный трекинг крупных чисел воспроизвести нечем, поэтому кегли и веса перенесены точно, а сжатие опущено |
| Веса шрифта 550 и 650 | WPF знает только именованные веса, взяты ближайшие: Medium и SemiBold |
| Внешний вид тумблера | Макет описывает выключенное состояние сплошной серой заливкой, но настоящий тумблер Windows 11 — это контур с почти прозрачной заливкой и ползунок 12 px. Взята системная геометрия (40×20, ползунок 12×12, плавное перемещение): программа должна выглядеть как приложение Windows 11 |
| Стартовый размер окна | 1120×760 вместо рабочей ширины макета 1240 px — окно не занимает пол-экрана при первом запуске. Вёрстка тянется, минимум 880×560 |
| Пути папок в отчёте | Показываются относительно проверенной папки: общий префикс у всех строк одинаков и только съедает место. Полный путь — в подсказке |

Подробности каждого решения — в комментариях рядом с соответствующим кодом.
